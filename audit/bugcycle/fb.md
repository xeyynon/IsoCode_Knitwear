## Not changed, and why

- **FE-X-07, no Content-Security-Policy:** not added. A policy that is wrong breaks the app and the service worker, and it cannot be tested until it is deployed. Known gap; the app has no raw-HTML sink (`dangerouslySetInnerHTML`, `innerHTML`, `eval`) and the sign-in token is the only thing in `localStorage`.
- **FE-X-09, `optimised.md` is tracked:** not untracked. The README links it on purpose as the public speed-and-cost record; removing it would break that link and the Markdown link check. The older `bug.md` files stay in the history (rewriting history would also lose the commit history the brief asks to keep). If the logs should be private, change the README sentence instead.
- **FE-X-10:** informational (a repeated `clientUuid` from a second account is acknowledged as a duplicate), no change.

## How the client address is worked out (for FE-X-01)

`req.ip` comes from Fastify's `trustProxy`. On Vercel (`vercel.ts`) `trustProxy` is `parseTrustProxy(env.TRUST_PROXY ?? '1')`, so with nothing set one proxy hop is trusted: the address is the last entry of `X-Forwarded-For` (what Vercel's edge saw), not whatever the caller wrote first. On the plain Node server (`server.ts`) it is off unless `TRUST_PROXY` is set. So on the live deployment the limiter counts per real client address, as intended. IPv6 addresses are counted by their /64.
